## Summary

LLP 0059 says which APIs Exact uses. This says what to build: for each one, the
surface, which side of the boundary owns what, its capsec posture, and what is
deliberately partial in v1.

Entries carry their provenance. **Measured** means LLP 0059 found it in
application code. **Author-required** means Charlie named it as something to
build on — a requirement, not a prediction, and the only kind of unmeasured
entry §7 admits. Both are v1; the marker exists so a later reader does not
mistake one evidence standard for the other.

Every API here is one of three shapes, and the shape decides most of the rest:

- **Pure** — no platform authority or capability. Most are computed in Rust;
  `structuredClone` is the explicit engine-owned exception and traverses the
  engine's value space through captured intrinsics. `URL`, `TextEncoder`,
  `atob`, `structuredClone`.
- **Delegating** — Rust owns semantics, the platform owns transport. `fetch`.
- **Ambient** — reads or writes process- or device-scoped state. `process.env`,
  `localStorage`, `crypto`. These are the capability-bearing ones.

## 1. The host-call boundary

One surface for every Tier I API that reaches Rust. Engine-owned operations
such as `structuredClone` do not manufacture a crossing merely to satisfy this
diagram.

```
hostCall(op: u32, args: HostValue[]) -> HostResult
```

Four properties, all cheap now and expensive to retrofit:

1. **Primitives and handles only.** Numbers, strings, `ArrayBuffer`s, and opaque
   handles. No JSON at the boundary; a `fetch` that serializes has traded parse
   time for call time.
2. **No new synchronous cross-thread surface** (LLP 0057 §3, LLP 0297). An op
   that leaves the calling thread returns a promise. An op that does not leave
   it returns directly. Which is which follows from the op's shape, not from a
   per-API decision — see §1.1 below.
3. **The capability check is here.** One chokepoint, before dispatch. This is
   the whole of LLP 0057 §4: an operation either carries a grant or is refused,
   and no capability is reachable by any other path.
4. **Buffers cross by handle, not by copy.** In both directions, and not merely
   as an aspiration — see §1.2.

### 1.1 Which ops are synchronous

The three shapes in the Summary decide this, and they decide it completely:

- **Pure** ops compute on the calling thread and never leave it. Rust owns the
  ordinary pure operations; `structuredClone` runs inside the engine over
  captured intrinsics because its input is the engine's object graph.
  They are **synchronous**, because they are not cross-thread calls at all and
  the rule in property 2 has nothing to say about them. `new URL(...)`,
  `encoder.encode(...)`, `btoa(...)`, and `structuredClone(...)` are
  synchronous web APIs; no application can await them, and a runtime that made
  them thenable would not be implementing those APIs.
- **Delegating** ops hand work to the platform and are **asynchronous**,
  without exception. `fetch`, `fs`, `WebSocket`.
- **Ambient** ops read or write process- or device-scoped state. They are
  asynchronous unless §2 names them.

An earlier revision of this section said `hostCall` returns a promise with the
only exceptions being §2's two. Read literally that made every pure op
asynchronous, which is not implementable: `new URL()` cannot return a promise
and remain `URL`. The rule was always LLP 0057 §3's — *no new synchronous
**cross-thread** call surface* — and the word doing the work is cross-thread.
§2 is therefore not a list of exceptions to synchrony; it is a list of ops that
**do** cross a thread and are synchronous anyway, which is a much shorter and
more suspicious list, as it should be.

### 1.2 What "by handle" requires

Property 4 is the one that is expensive to retrofit, so it is stated as a
requirement rather than a preference.

**Inbound**, a JavaScript `ArrayBuffer` argument reaches Rust as a borrowed
span over the engine's own allocation, valid for the duration of the call and
not beyond. Rust must not copy it to inspect it. Where an API writes into a
caller-supplied buffer — `encodeInto` is the motivating case — the span is
mutable and Rust writes through it, so the effect is visible to JavaScript in
the buffer it already holds. This is the reason `ArrayBuffer` is in the
boundary contract at all; an `encodeInto` that copies has implemented `encode`
with extra steps.

**Outbound**, a Rust byte buffer becomes an `ArrayBuffer` backed by that same
allocation, whose ownership transfers to the engine. The engine frees it
through the boundary when the object is collected. There is no intermediate
copy and no second allocation.

**Strings are different, and the difference is the engine's, not ours.** A
JavaScript string has an engine-chosen internal representation, so obtaining
UTF-8 bytes from one allocates. String arguments therefore cost one copy that
no boundary design can remove. This is a reason to prefer `ArrayBuffer` for
anything large, not a reason to relax property 4 for buffers.

### 1.3 What each crossing costs, measured

Measured against vanilla Hermes on an 8 MB payload (`crates/ibex2`,
`measure_boundary_costs`, release, mean of 20, stable across runs). Per MB of
UTF-8:

| crossing | cost per MB |
|---|---|
| bytes in — borrowed span | **~0** (≈45 µs regardless of size) |
| bytes out — ownership transfer | **~0** |
| string out | ~0.7 ms |
| ASCII string in | ~2 ms |
| non-ASCII string in | ~3.5 ms |

Two conclusions follow, and they are the reason this section exists.

**Bytes are free in both directions and strings are not.** The asymmetry is not
a defect in the boundary; it is that a JavaScript string has an engine-chosen
representation and obtaining UTF-8 from it is a conversion, while an
`ArrayBuffer` is already a byte range. No boundary design removes it.

**So large payloads cross as bytes, and this is a design rule rather than an
optimization.** `fs.readFile` yields bytes and text is opt-in through
`TextDecoder`; `fetch` bodies and `Response.arrayBuffer()` are bytes;
`Response.json()` hands bytes or text to the engine's own `JSON.parse` rather
than parsing in Rust, which §1.1 forbids anyway. Under that rule the delegating
APIs cost nothing at the boundary: a read is a small path string plus a
zero-copy byte result.

**Module bytecode is the case where this decides whether the budget is met.**
LLP 0057 §1 measures the current boot path as shipping 5.47 MB of module
sources as string literals. Crossing that as strings would cost roughly 11 ms
at the ASCII rate — against the 30 ms budget in `rules/RULES.md`, before any
work is done. Crossing it as bytes costs approximately nothing. A future module
loader that passes source or bytecode as a string has reintroduced the cost
LLP 0057 exists to delete.

Where a copy genuinely cannot be hidden is a pure op with no I/O behind it —
`encodeInto` being the motivating case, which is why it writes through to the
caller's buffer. For a delegating op the copy is bounded by one conversion and
sits behind a network or disk operation that costs more.

## 2. Synchronous cross-thread exceptions

Per §1.1, pure ops are synchronous as a matter of course and are not exceptions
to anything. This section is the complete list of ops that **do** leave the
calling thread and are synchronous anyway — each because its own web contract
is synchronous and cannot be made async without breaking application code:

- **`localStorage`** — the web contract is synchronous. It must not become a
  cross-thread blocking call. **v1 resolution: the store is mirrored into the
  engine's realm at boot and written through asynchronously.** Reads hit the
  mirror; writes update the mirror synchronously and enqueue a durable write.
  The cost is that a write is not durable when the call returns, which is
  acceptable for the measured uses (22 uses across 7 modules, all UI
  preference state) and must be stated in the binding's documentation.
- **`performance.now`** — sync, but it reads a clock rather than calling a
  service. **v1 resolution: a shared-memory read of the frame clock's time
  base**, not a host call. It must be the same base the host uses for
  `requestAnimationFrame` and motion, or animation and scheduling drift.

Any third candidate needs an entry here and a reason. That list is the whole
exception surface.

## 3. The APIs

### 3.1 `console` — pure, ungated

`log` `warn` `error` `info` `debug`. Formatting happens in Rust so it is
identical across engines. **Non-blocking**: writes enqueue and flush on a
timer or at a size threshold. 214 uses across 89 modules makes this the most
frequently called API in the system; a synchronous flush per call is a
startup regression on its own.

Out of v1: `table`, `group`, `time`, `trace`, `dir`, `count`, `assert`.

### 3.2 Timers — pure, ungated

`setTimeout` `setInterval` `clearTimeout` `clearInterval`. Integer handles.
Clamping and ordering follow the HTML spec: same-delay timers fire in
insertion order. The timer wheel lives in Rust; expiry enqueues a task into
the engine job queue through the LLP 0058 §3 adapter.

Out of v1: `setImmediate`, `requestIdleCallback`.

### 3.3 `TextEncoder` / `TextDecoder` — pure, ungated

`TextEncoder`: `encode`, `encodeInto`. `TextDecoder`: `decode` with `stream`.
**UTF-8 only in v1.** The measured uses are all UTF-8; `latin1`, UTF-16, and
the legacy label set are out. `fatal` and `ignoreBOM` are honored.

Buffers cross the boundary by handle. `encodeInto` writing directly into a
caller-supplied `Uint8Array` is the reason `ArrayBuffer` handles are in the
boundary contract at all.

### 3.4 `URL` / `URLSearchParams` — pure, ungated

Full WHATWG URL parsing, including IDNA and percent-encoding rules, because a
partial URL parser is a security bug rather than a missing feature. This is
pure Rust and should be a well-tested crate rather than hand-written.

`URLSearchParams`: construction from string, object, and pairs; `get`,
`getAll`, `set`, `append`, `delete`, `has`, iteration, `toString`.

*Built 2026-08-29.* The Rust side had passed WPT since the first day and had
no binding — found when timing Exact's boot, whose `pathnameForRoute` wraps
`new URL(path, base)` in a `try/catch` that routed every path to `/`. The
binding holds shape only: a `URL` keeps the eleven components the parser
returned and every setter asks Rust for the URL as it is after the assignment,
so setter semantics are the `url` crate's, which are the spec's (silent
failure everywhere but `href`). A `URLSearchParams` holds its serialized query
string and nothing else; each method is one crossing that reads or rewrites
it in Rust, which gives order, duplicates, and form-urlencoded escaping one
implementation, and makes `url.searchParams` a live view — it reads and
writes `url.search` rather than keeping a copy. Also `URL.canParse`,
`URL.parse`, `has`/`delete` with a value, `sort`, `size`. Iteration hands
out a snapshot. Two setter details a review caught the same day: the `host`
setter takes the port's leading digits and leaves the port alone when there
are none (`x:80abc` is host `x` port 80; `x:` changes only the host), and the
`protocol` setter reads up to the first colon (`http:garbage` sets `http:`).

### 3.5 `fetch` — delegating, **capability-bearing**

The largest v1 item, and understated by its twelve call sites: a `Response`
implies `Headers`, body accessors, redirect policy, and abort.

**Rust owns:** header name case-folding and the forbidden-header list, redirect
following and its count limit, the body state machine, `AbortSignal`
integration, the response ceiling, and the error taxonomy — so failures are
identical on every platform.

**The platform owns:** sockets, TLS, proxy configuration, HTTP/2 and /3,
connection pooling, and the system certificate store.

**Response bodies are demand-driven.** Author-required, 2026-09-06: app
networking needs cancellation and incremental consumption. `Transport::open`
returns a `StreamingResponse` when the platform delivers headers; its `Body::read` blocks for the next
bytes without choosing an executor. `Fetch::stream(request, signal)` uses the
same origin admission and redirect loop as buffered `Fetch::send`/`get`, which
collect that stream. Dropping an unread body releases its native request.

`Request.max_body` remains a cumulative byte ceiling, `DEFAULT_MAX_BODY` (64
MiB) when omitted. Transports refuse oversized declared lengths at headers;
the common Rust body checks bytes incrementally and releases the source on
overflow, EOF, or error. The ceiling bounds both collected responses and total
stream consumption; a caller intentionally reading more must choose its limit.

**Credentials do not cross origins on a redirect.** When the follower takes a
redirect to a different origin, it deletes `Authorization`, `Cookie`, and
`Proxy-Authorization` from the next request, as the Fetch standard does for
`Authorization`. Same-origin hops keep the full list. This is required by the
subdomain grant (LLP 0067 §2): one grant admits sibling hosts, and a token
meant for one must not reach another.
Backpressure bounds unread transport data separately from that total quota.

JavaScript `fetch` resolves when the platform delivers headers, before body
completion. NSURLSession may wait for the first body byte before delivering
its header callback, even for event-stream or `nosniff` responses; a standalone
native delegate test reproduces this independently of Ibex. The portable
transport returns on the header block alone. This Apple latency deviation is
kept with its platform transport rather than adding another networking stack. `Response.body` exposes a private
response-body reader (`getReader`, `read`, `cancel`, `releaseLock`, `closed`,
`locked`); `bodyUsed` tracks disturbance. `text`, `json`, and `arrayBuffer`
asynchronously consume the same chunk path. This is a response reader subset,
not a general `ReadableStream` constructor or a claim of full Streams conformance.
A read returns bytes or EOF through a private handle; body I/O never holds the
runtime registry lock. The JS host executor reserves four body-read workers so
fetch opens waiting for session leases cannot starve the reads that release
those leases; both kinds of settlement still enter the same completion FIFO.
Cancellation interrupts native header/body waits, and
runtime destruction aborts outstanding requests. A JSI native owner cancels an
unread body when collected; collection timing is unspecified, so consumers
should consume or explicitly cancel bodies they retain. JavaScript retains the exact
abort reason without serializing it through Rust.

**Connection pools are runtime-owned.** Apple leases up to four NSURLSessions,
each with a serial delegate queue and a 64 KiB Ibex body queue (separate from
platform-owned buffers). A response releases its lease at native completion,
even if its buffered bytes are unread. A large unread body fills the queue and
holds its active lease; opening a fifth active response waits cancellably. This keeps
callback order and connection reuse without allowing one slow reader to block
all other requests. The portable transport leases ureq agents, retaining up to
eight idle agents. A completed response returns its lease; dropping an unfinished
response cancels its request. Old cancellation signals cannot close connections
subsequently reused by another lease. Pools never cross runtime boundaries.
Portable system DNS runs synchronously on the caller's thread and cannot be
interrupted mid-resolution; cancellation is checked immediately afterward.

v1 surface: `fetch(input, init)` with `method`, `headers`, `body`, `signal`,
`redirect`. `Response`: `status`, `ok`, `headers`, `url`, `text()`, `json()`,
`arrayBuffer()`, `blob()`. `Headers` and `Request` constructible.
Calling `fetch()` with no URL rejects with a `TypeError` naming the missing URL.

With both `BLOB` and `FETCH` installed, `Request` and `fetch` accept `Blob` and
`FormData` bodies. A non-empty Blob type supplies `Content-Type` only when the
caller did not author one. FormData's ordered entry list crosses synchronously
to the Rust RFC 7578 encoder; that call generates the OS-CSPRNG boundary,
returns the complete bytes, and supplies `multipart/form-data; boundary=…`
with the boundary value always quoted, under the same authored-header rule.
The JavaScript and engine-free Rust paths use the same rule. `URLSearchParams`
remains
`application/x-www-form-urlencoded;charset=UTF-8`. The groups are independent:
installing `FETCH` without `BLOB` adds none of the Blob family or its response
methods and preserves the byte/string request path.

`Response.blob()` consumes the same one-shot body as the other readers. Its
type is the response Content-Type after Fetch MIME-type extraction. The
combined header value is split on commas outside quoted strings; invalid and
`*/*` items are skipped; the last valid item wins; and a charset parameter is
carried through later items only while their essence stays the same. The
selected MIME type is serialized under MIME Sniffing, or the empty string is
used when no valid item remains.
Buffered response helpers assemble chunks into a fresh genuine `ArrayBuffer`
using only constructors, typed-array accessors, and `set` captured during
bootstrap. In particular, `Response.blob()` cannot be redirected to a
caller-controlled buffer by shadowing `Uint8Array.prototype.buffer` in an
unhardened caller-owned runtime; the completed bytes are copied before they
become the Blob's private immutable state.
`Response.formData()` parsing is not in v1; in the combined groups it rejects
a `DOMException` named `NotSupportedError`.

**Request headers cross by handle.** The JavaScript binding unpacks
`RequestInit`, constructs a fresh `Headers` from its record, pairs, or
`Headers` instance, and passes its numeric handle as argument five after URL,
method, body bytes, and redirect mode. This snapshots the caller's list before
the async crossing and reuses Rust's normalization without a JSON round trip
(§1). Rust checks that the handle is a positive safe integer registered in this
runtime, validates the stored names as HTTP tokens and the normalized values
as header bytes without NUL, CR, or LF and with no code point above U+00FF,
then clones the list into `Request`.
A malformed argument, unknown handle, or invalid list rejects with
`HostError::InvalidArgument`; an omitted or `undefined` fifth argument means an
empty list; explicit `null` is invalid, not absent. The binding frees its fresh
snapshot through the existing Headers free op after the raw call settles,
whether it succeeds or rejects (also on a synchronous raw-call throw or failed
Headers initialization). Rust only clones: a raw caller retains ownership of
its live `Headers` handle and may reuse it across calls. The request guard still
removes transport-owned headers, and the origin grant is still checked before
each transport call. `follow` retains the cloned list across granted hops and
does not drop body headers on a method rewrite. The one exception is the
credentials, which a cross-origin hop drops (below). The rest of Fetch's strip
rules are the consumer's responsibility (Snapback follows hop by hop) or a
later Ibex change. *(2026-09-05: Snapback 2's
effects authored content type, authorization, and an idempotency key; the
four-argument boundary discarded them before the platform could send them.)*

Out of v1: streaming request bodies, general-purpose `ReadableStream`, `cache`
and `credentials` modes, response FormData parsing, service workers.

**Capability:** `net.fetch`, granted per-origin. This is the operation the
supply-chain story is about; a package without the grant cannot reach the
network by any path, because there is no other path.

### 3.6 `AbortController` / `AbortSignal` — pure, ungated

`abort(reason)`, `signal`, `aborted`, `reason`, `addEventListener('abort')`,
`AbortSignal.abort`, `AbortSignal.timeout`, `AbortSignal.any`, `throwIfAborted`.
Rust callers use `stdlib::abort::AbortController` and its clonable `AbortSignal`;
registration bridges cancellation into the native transport. No Rust clock or
executor is installed. JavaScript timeout uses the existing runtime timers.

Implemented in L3. With `EVENTS` installed, `AbortSignal` inherits
`EventTarget`, dispatches a real non-cancelable trusted `Event("abort")`, and supports
`onabort`; without `EVENTS`, its original private listener list and event-shaped
object are retained exactly so `ABORT` has no new dependency. `timeout()` does
not give `ABORT` a `TIMERS` dependency: it throws a `NotSupportedError`
`DOMException` when that group is absent. `any()` records flattened source
signals, marks the dependent graph before any abort dispatch, keeps the first
aborted input's reason, and removes dependent registrations after abort.

### 3.7 `localStorage` — ambient, **capability-bearing**

`getItem` `setItem` `removeItem` `clear` `key` `length`, plus index access.
Strings only. Mirrored per §2. Scoped per application, not per package.

**Capability:** `storage.local`. Out of v1: `sessionStorage`, the `storage`
event, quota reporting.

### 3.8 `process.env` — ambient, **capability-bearing**

Read-only. Returns a snapshot object, not a live proxy.

**Capability:** `env.read`, granted per-variable-name. This is the canonical
supply-chain case — a package reading `AWS_SECRET_ACCESS_KEY` — and a
per-variable grant is what makes the refusal meaningful rather than
all-or-nothing.

Out of v1: writes, `process.argv`, `process.cwd`, `process.exit`, everything
else on `process`.

### 3.8.1 `MessageChannel` / `MessagePort` — removed

Specified and built on 2026-08-28 for React's renderer; removed the same
evening with LLP 0059 §6's entry when the target moved to Exact 2 (LLP 0057
§5.2). The binding, its three tests, and the structured-clone ticket went with
it; history has them at `60c19f0dc`.

### 3.9 `crypto` — ambient, partially gated

`crypto.randomUUID()` and `crypto.getRandomValues()`. Both draw from the
platform CSPRNG. **Ungated** — neither conveys authority, and gating them
would train people to grant capabilities reflexively, which is how a
capability system dies.

**Implemented 2026-09-06 (Codex):** `stdlib::crypto::get_random_values(&mut [u8])`
and `random_uuid()` call the OS CSPRNG through `getrandom`, with no engine,
manifest grant, or host object required. The byte fill enforces WebCrypto's
65,536-byte per-call ceiling before mutation, accepts an empty slice, and
clears the destination and returns `OperationError` on entropy failure. UUIDs
set the v4 version/variant bits and format lowercase hexadecimal in Rust.

The bytecode binding installs `Crypto` and `crypto`. It validates the receiver
and integer typed-array brand (including BigInt views), passes the backing
ArrayBuffer plus intrinsic offset/length through host op 71, and returns the
original view. No user-overridable view property supplies a native pointer or
length; Rust validates the range and quota before borrowing it mutably. Op 70
returns the Rust UUID. Bootstrap functions are removed before application code.
The small shared `DOMException` and `QuotaExceededError` bindings supply the
web error classes, names and legacy codes. The `crypto.subtle` implementation,
scope limits, and evidence are recorded in §3.14.

Evidence is `tests/crypto.rs` (Rust, raw ABI and hardened Hermes) and the

### 3.10 `atob` / `btoa`, `structuredClone`, `Blob` / `File` / `FormData`, `CustomEvent` — pure, ungated

`atob`/`btoa`: base64 in Rust, throwing on invalid input per spec.

`structuredClone`: the structured clone algorithm over the engine's value
space — objects, arrays, `Map`, `Set`, `Date`, `RegExp`, typed arrays, and
cycles. **No transferables in v1** (one measured use).

**Implemented 2026-10-04 (Codex):** the precompiled JavaScript binding clones
primitives and boxed primitives; ordinary objects to plain objects, invoking
enumerable own string-keyed getters in key order, rechecking ownership before
each read; sparse arrays plus extra
enumerable properties; `Date`; `RegExp` with a reset `lastIndex`; `Map`; `Set`;
`ArrayBuffer`; every typed-array constructor Hermes provides; `DataView`; and
the seven standard Error kinds, including `message`, `cause`, and `stack` when
present; and `DOMException` from its serialized `name` and `message`. One
memory map preserves cycles, shared references, and shared cloned buffers
across views. Primitive `options` values fail WebIDL dictionary conversion.
`transfer` is converted in one pass as WebIDL `sequence<object>`: its iterator
method is read once, each element is converted as it is yielded, and an element
conversion failure closes the iterator (so a non-iterable array-like or a
primitive member throws `TypeError`). An absent or empty sequence works and any
nonempty sequence throws `DOMException` `DataCloneError` with "transfer is not
supported".

Every intrinsic used by traversal, allocation, collection mutation, and engine

recognized with captured internal-slot getters or methods (`Map.prototype.has`,
the `ArrayBuffer`/typed-array/DataView getters, wrapper `valueOf`s, and their
equivalents), not application properties. The captured `TextEncoder.encode`
method and `TextDecoder.encoding` getter identify and refuse those engine-owned
instances instead of cloning them as empty ordinary objects; merely inheriting
one of their prototypes is not sufficient. The captured `ArrayBuffer.detached`
getter makes a detached buffer or view fail as `DataCloneError`; this runtime
does not expose a way to create one because transfers and Hermes's test-only
detach methods are disabled, so the positive detached case cannot be exercised
through its production surface. When that getter exists it is the only detached
signal: allocation and reconstruction failures, including `RangeError`,
propagate unchanged. The getter-less engine fallback maps only the engine's
detached-buffer `TypeError` to `DataCloneError`.

Ibex platform identity uses one bootstrap-only private `WeakMap`. Its reader
and writer close over bootstrap-captured, uncurried `WeakMap.prototype.get`
and `set`, so an unhardened caller-owned runtime cannot interpose on an access,
recover the registry, or write a forged platform brand. Each factory captures
the `brand(object, kind, data)` writer, and the final PURE script captures the
reader and deletes both bootstrap globals. The registered kinds are
`Headers` and its iterators; `URL`, `URLSearchParams`, and their iterators;
`DOMException`; `QuotaExceededError`; `Crypto`, `SubtleCrypto`, and
`CryptoKey`; `AbortController` and

(`CryptoKeyPair` is a WebIDL dictionary represented by an ordinary object,
not a separately branded platform object; traversing one still reaches its

`Blob` and `File` are serializable: deserialization creates a new platform

serialize from their recorded data. Every other registered object, including
`FormData`, its iterators, `Request`, `Crypto`, `SubtleCrypto`, `CryptoKey`,
every `Event` and event-subclass instance, every constructed `EventTarget`,
and `navigator`,
throws `DataCloneError`. Changing
a registered object's prototype or tag does not change its identity; a plain

WebCrypto `CryptoKey` is serializable in browsers; Ibex2 refuses it because

### 3.11 `fs` — delegating, **capability-bearing** *(author-required)*

Promise-based only. `readFile` `writeFile` `appendFile` `readdir` `mkdir`
`rm` `stat` `rename` `copyFile` `realpath`, each returning a promise, plus
`createReadStream`-shaped iteration deferred with the rest of streams (§5).

**No synchronous variants.** `readFileSync` and its family are the largest
single source of blocking in Node programs, and LLP 0297 forbids the
cross-thread sync call they would require. This is a deliberate divergence
from Node and should be documented as one.

Paths resolve through the existing virtual filesystem namespace rather than
the raw OS path space, so a grant is expressible as a subtree.

**Capability:** `fs.read` and `fs.write`, **granted per path prefix**. This is
the second half of the supply-chain story — the package that cannot read
`~/.ssh` — and per-prefix is what makes it meaningful rather than a single
all-or-nothing switch.

**App-scoped paths (author-required, 2026-09-07).** The host supplies existing
absolute data, cache, and temporary directories using `AppDirectories::new`.
`Host::with_app_directories` or `Hermes::set_app_directories` binds those roots;
configuration is explicit and per host/runtime, with no ambient defaults.
Apps use `app:/data`, `app:/cache`, and `app:/tmp`; JS exposes these names as
frozen `fs.directories.data`, `.cache`, and `.temporary`. Names grant nothing.
Manifest prefixes such as `fs.write app:/data/settings` remain separate from
native absolute-path grants and from other mounted roots.

Every existing FS method accepts app paths. App operations use pinned Unix
directory handles and refuse dot traversal and symlink traversal. Mixed native/app two-path operations are rejected; cross-root app operations
require grants on both paths. Root renaming cannot retarget
an already-open app filesystem capability. Non-Unix app operations fail closed.
`realpath` returns the normalized app path, not a physical host path.

`atomicWriteFile` / Rust `atomic_write_file` writes a random, exclusively created
0600 temporary file in the pinned destination parent, syncs its contents, and
atomically renames it over the target. Failure before rename cleans up the
temporary file and leaves the previous target intact. This promises atomic
visibility; it does not sync the parent directory or promise power-loss
durability. `rename` requires source read and write plus destination write;
`copyFile` requires source read and destination write.

### 3.12 `WebSocket` — delegating, **capability-bearing** *(author-required)*

The WHATWG interface: constructor with protocols, `send` (string,
`ArrayBuffer`, `ArrayBufferView`, `Blob`), `close(code, reason)`,
`readyState`, `bufferedAmount`, `binaryType`, and the `open` `message` `error`
`close` events.

**Rust owns:** URL/grant/protocol/close validation, state, event vocabulary,
backpressure accounting, and — on the portable transport — masked RFC 6455
framing, fragmentation, ping/pong, and the closing handshake. **The platform
owns:** the socket, TLS, and proxy traversal. On Apple the selected platform
unit is `NSURLSessionWebSocketTask`, so it also owns framing and its send queue;
Rust presents the same message-level trait above both transports.

Ibex already speaks WebSocket internally for the dev connection. That is a
runtime-internal transport; this is the application-facing binding, and they
should share the Rust implementation rather than growing a second one.

**Capability:** `net.websocket`, per-origin.

Out of v1: application-defined subprotocol selection callbacks and
`permessage-deflate`. Blob transmission requires the `BLOB` family. Until it
is installed, setting `binaryType = "blob"` is accepted but incoming binary
messages use the documented `ArrayBuffer` fallback, and Blob send is
unavailable.

**Implemented 2026-10-04.** The original receive-only Rust surface remains
source-compatible: `Bindings::websocket.open`, `MessageSource::next`, and
`Incoming` retain their signatures and meanings for exact2. Additions are
`MessageSender`, `Connection`, payload-bearing `Message`/`Event`,
`send_text`, `send_binary`, `close`, `buffered_amount`, and
`Bindings::websocket.watch`. A watch returns L3's
`std::sync::mpsc::Receiver<Event>` and `Subscription`; JavaScript consumes the
same source through `HostTask::Event` in the one host FIFO.
The legacy `MessageSource::next()` binary result remains receive-only in the
strong sense exact2 already depends on: it returns the first binary frame's
declared length before reading or allocating that frame's payload, including
for a fragmented message. Only `next_event()` assembles a complete binary
payload.

Client data frames are masked and the portable transport fragments messages at
16 KiB. Script close codes are 1000 or 3000–4999 and reasons are at most 123
UTF-8 bytes. Sending while CONNECTING throws `InvalidStateError` in JavaScript;
sending while CLOSING/CLOSED queues nothing and permanently grows
`bufferedAmount`, including after a transport error. A valid close performs the
closing handshake. The portable writer serializes whole fragmented messages.
Reads and writes share the one rustls protocol state; an announced queued
writer has priority before the receive loop reacquires that connection after a
timed read. Platform mutex fairness is not a progress condition. This same
arbitration is used in portable tests on Apple, although the production Apple
transport remains `NSURLSessionWebSocketTask`.
Apple uses `sendMessage` completion callbacks for the same accounting.
Send admission/accounting remains under the per-socket condition through the
platform `sendMessage` submission, and close holds that same condition from
its state transition through `cancelWithCloseCode`. Concurrent send and close
therefore have one atomic platform-submission order: an admitted send is
submitted before close, or closure wins admission and no data is submitted.

Queues have per-socket ceilings. Portable and Apple outbound queues admit at
most 256 data messages and 16 MiB of data payload at once. A full portable
queue fails the connection abruptly, the WHATWG full-buffer path when even a
close frame may be stuck behind a non-reading peer; Apple asks its platform
task to close with 1009. The portable command channel has 272 slots — the 256
data-message ceiling plus 16 control-frame slots — and every data, close, pong,
and other control command uses nonblocking admission. Exhausting those slots
also fails the connection abruptly rather than attempting a 1008 close that
the same blocked writer cannot be trusted to drain. Further script sends are not handed to either
transport and only increase `bufferedAmount`. The executor-neutral Rust watch
has two event slots (enough for terminal `error`/`close`) and pauses socket
reading while its consumer stops receiving. JavaScript host-task admission
allows at most 256 events or 32 MiB per subscription and likewise pauses its
producer until the runtime pumps or unsubscribes. Unsubscribe clears shared
liveness before aborting and publishes no cancellation event.

An open socket is an L3 subscription. It publishes `open`, text/binary
`message`, `error`, and `close { code, reason, wasClean }` in transport order.
Queued `open` and `message` tasks are accepted only while the script object is
respectively CONNECTING and OPEN. `close()` while CONNECTING fails the
connection without an `open`; every failure sets CLOSED before `error`, then
delivers `close`. A weak native owner breaks the callback/socket cycle. The
runtime roots a socket only for WHATWG's listener and queued-outbound-data
conditions, rechecks the actual EventTarget listener list before collection,
and unsubscribe/collection closes the native source without a late event.
EventTarget's actual add/remove path reports mutations through one
bootstrap-private hook retained by the adapter rather than published on a
global or platform object. Signal abort, `once` dispatch, and direct calls to
the base prototype therefore update the same keepalive state and synchronously
release the strong root when the condition ends.
No-argument close is exposed as code 1005 on both transports even though
NSURLSession must put 1000 on its wire.

The `WEBSOCKET` install group depends on `PURE` and `EVENTS` and is included in
`Groups::DEFAULT` and `Groups::ALL`. It provides the WHATWG constructor and constants,
`MessageEvent`, `CloseEvent`, handler properties, URL scheme mapping and
fragment/credential refusal, case-insensitive duplicate-protocol rejection,
and subprotocol selection. Admission precedes transport creation; denial
publishes `error` then unclean `close` 1006 without opening a socket.
The secure runtime creates that constructor from each module's grant and
passes it as the final lexical wrapper parameter; no `WebSocket` global
remains. A caller-owned runtime retains an installer-endowed global, matching
its existing `fetch` posture.

`websocket` is a cargo feature. It is default on: the post-main-merge stripped
run-only delta is 36,992 bytes and the best paired startup delta is 41.0 µs,
inside LLP 0057.000 D5's 150 KB / 150 µs limits. With the feature off, the Rust
transport returns `Unavailable { feature: "websocket" }` and the JavaScript
constructor throws `NotSupportedError`; the group shape still exists so builds
fail by behavior rather than a missing symbol.

The L4 transport decision is final: keep `NSURLSessionWebSocketTask` on Apple.
Send needs nothing its message API cannot provide, and retaining it preserves
system proxy/VPN/trust behavior. Off Apple, TCP and rustls use the same native
trust-store policy as fetch. Plaintext and pinned loopback-TLS echo/close tests
run on both implementations, including the portable implementation on Apple.
The pinned unmodified local-echo WPT subset passes 41/41, with WPT-server,
generated-domain, HTTP/2, Window, worker, Blob, and policy fixtures recorded as
named exclusions in `third_party/wpt/MANIFEST.json`.

### 3.13 `Buffer` — pure, ungated *(author-required)*

A `Uint8Array` subclass, as in Node, so a `Buffer` is accepted anywhere a
typed array is.

v1: `Buffer.from` (string with encoding, array, `ArrayBuffer`, `Buffer`),
`Buffer.alloc`, `Buffer.allocUnsafe`, `Buffer.concat`, `Buffer.isBuffer`,
`Buffer.byteLength`; and on the instance `toString(encoding)`, `slice`,

### 3.14 `crypto.subtle` — pure, ungated *(author-required)*

Operations on caller-supplied key material. Ungated for the same reason as
`getRandomValues` (§3.9): computing a digest conveys no authority, and gating
harmless operations trains people to grant reflexively.

v1: `digest` (SHA-256, SHA-384, SHA-512); `importKey` and `exportKey` (`raw`,
`pkcs8`, `spki`, `jwk`); `sign` and `verify` (HMAC, ECDSA P-256, Ed25519);
`encrypt` and `decrypt` (AES-GCM); `deriveBits` and `deriveKey` (HKDF,
PBKDF2); `generateKey` for the above. `CryptoKey` is an opaque handle whose
material never crosses into the engine unless the key is `extractable` and
`exportKey` is called.

Backed by the vetted crate already vendored in this repository rather than a
new implementation. **SHA-1 and MD5 are not provided**, in either direction.

Out of v1: RSA in all forms, AES-CBC and AES-CTR, X25519 key agreement,
`wrapKey`/`unwrapKey`. A persistent key store is out and would be
capability-bearing when it arrives — the operations are harmless, but custody
of a key is authority.

**Implemented (L2), 2026-10-04.** Door 1 is `stdlib::subtle`: typed
hash/import/generate/derive/AES parameters, an owned `CryptoKey` whose debug
representation excludes material, WebCrypto-named errors, and engine-free
operations backed by the workspace's **unmodified vendored `ring`**. D6 splits
the code by measured cost. Default-on `crypto` provides SHA-256/384/512,
HMAC, AES-GCM, HKDF, and PBKDF2. Default-off `crypto-asymmetric` implies
`crypto` and adds ECDSA P-256, Ed25519, and the SPKI/PKCS#8 DER codec. The
bindings keep the same shape when either feature is absent and reject with a
named `NotSupportedError` saying which build feature omitted the operation.

AES-GCM is exactly the backend's surface: 128- and 256-bit keys, 96-bit IVs,
and 128-bit tags; AES-192 is explicitly `NotSupportedError`. Caller-selected
derived output and HMAC key lengths are capped at 1,000,000 bits. HKDF also
applies its algorithmic ceiling of 255 times the selected hash output and a
checked 65,536-compression-block combined-work budget. For hash `H`, admitted
work is the number of output blocks times the compression blocks needed for
`info || counter || T(i-1)`, plus the compression blocks needed to process the
salt and input key material during extract. This admits about 16 KiB of
SHA-256 `info` and 32 KiB of SHA-512 `info` even at the 255-block output
maximum, while refusing a multi-megabyte `info` before `ring` is called. The
same preflight applies through `deriveKey`. PBKDF2 is a pure synchronous
operation under §1.1, so iterations are capped at
1,000,000 and salt at 125,000 bytes, and a checked combined-work limit prevents
the two individually valid maxima from multiplying into billions of PRF
calls. For hash `H`, admitted work is the product of
`ceil(outputBytes / H.outputBytes)` and `(iterations + saltBlocks)`, where
`saltBlocks` is `ceil((saltBytes + 4) / H.compressionBlockBytes)`. It may not
exceed one output block at both maxima:
1,001,954 units for SHA-256 and 1,000,977 for SHA-384 or SHA-512. Boundary and
just-over-boundary tests cover each hash. Every algorithm, size, usage, and
work check occurs before caller-sized output or owned key allocation.

Import follows the same preflight rule. Raw AES-GCM/HMAC key size and
HKDF/PBKDF2 extractability/usages are checked against borrowed bytes before
copying. `KeyFormat` is the case-sensitive enum `raw | spki | pkcs8 | jwk`;
other spellings, including case variants, produce `TypeError` on import and
export. The ABI caps borrowed JWK `kty`, `k`, `crv`, `x`, `y`, `d`, `alg`,
`use`, and every `key_ops` string before constructing owned strings; semantic
validation precedes base64 decoding. Raw public points and SPKI/PKCS#8 inputs
are usage- and size-checked before copying or DER parsing. These checks make
hostile allocation attempts named failures without first allocating in
proportion to the hostile input.

WebIDL fields declared `[EnforceRange]`—including HMAC key length, AES key/tag
length, and PBKDF2 iterations—use that conversion in JavaScript and repeat
the bounds at the Rust ABI. The current
[Web Cryptography editor's draft](https://w3c.github.io/webcrypto/) declares
`deriveBits` length as `optional [EnforceRange] unsigned long? length = null`.
Omitted, `undefined`, and `null` therefore become null and produce
`OperationError`, but only after the algorithm/key match and `deriveBits`
usage checks, so an inaccessible or mismatched key still produces
`InvalidAccessError` first. Non-null NaN, infinities, negative values, and
values above 2^32−1 produce `TypeError`; BigInt and Symbol also produce
`TypeError`. Numeric zero remains a valid empty derivation.

HMAC lengths are bit-granular for **import and generation**: storage is
`ceil(length / 8)` bytes, unused low bits in the last byte are cleared, the
declared bit length remains in `CryptoKey.algorithm`, and raw/JWK export emits
only that masked representation. Import follows WebCrypto's rule that a
declared length at least one whole byte shorter than the supplied material is
`DataError`; it does not silently truncate extra bytes. `deriveKey` passes the
requested HMAC length through unchanged, so a non-octet length reaches the
HKDF/PBKDF2 derive-bits step and rejects with `OperationError`. A zero HMAC
length in `deriveKey` is the get-key-length `TypeError`; `generateKey` with
zero remains `OperationError`. HMAC generation draws bounded material directly
from the OS CSPRNG in chunks; the 65,536-byte quota belongs only to the public
`getRandomValues` call.

The asymmetric subset supports ECDSA P-256 with SHA-256 and Ed25519.
Generation, signing, verification, and raw/SPKI/PKCS#8/JWK import/export use
the same key table. ECDSA signatures are the WebCrypto/IEEE P1363 64-byte
`r || s` form. The unmodified `ring` public API exposes fixed-length P-256
only with SHA-256, so P-256 with SHA-384 or SHA-512 rejects sign and verify
with `NotSupportedError`. A P-256 PKCS#8 private key must embed its public
point; when it does not, import returns `NotSupportedError` because `ring` has
no public API to derive that point. Ed25519 import can derive its public key
through `ring`'s public API. P-384, P-521, ECDH/X25519, RSA, SHA-1,
`wrapKey`, and `unwrapKey` remain named refusals. Generated public keys are
always extractable; private keys follow the caller's `extractable` argument.
ECDSA and Ed25519 generation requires `sign` in the requested usages because
the returned private key may not have an empty usage list; `verify` alone and
an empty list reject with `SyntaxError` before entropy is drawn.

The small DER module recognizes only Ed25519 and id-ecPublicKey/P-256 and the
exact SPKI/PKCS#8 wrappers needed here. Lengths are definite and minimally
encoded; parameters, versions, OCTET/BIT STRING nesting, unused-bit counts,
scalar/seed lengths, and the P-256 curve OID must match. It rejects trailing
bytes, wrong OIDs, Ed25519 parameters, explicit curves, compressed points,
and wrong-sized points. JWK import validates `kty`, `crv`, canonical unpadded
base64url coordinates, `alg`, `use`, and `ext`. The JWK ABI carries `key_ops`
as a count followed by separate strings rather than delimiter-joined text, so
element boundaries survive unchanged. One validator shared by oct, EC, and OKP
rejects unknown or duplicate entries and requires the requested usages to be a
subset of `key_ops`. It does not require every declared operation to be legal
for the imported asymmetric component: for example, a private EC JWK declaring
`["sign", "verify"]` may be imported for `["sign"]`.

The JavaScript projection is a precompiled thin binding on the same
synchronous host-call surface. Each method computes in Rust on the runtime
thread and returns an already-settled Promise, following §1.1 without a second
worker path. A `CryptoKey` wraps a numeric handle whose table entry owns all
material. A JSI `NativeState` releases that entry when the key is collected;
runtime shutdown clears the table before destroying the VM. The GC test
permits Hermes a bounded number of collections to retire conservative roots
from the just-settled Promise chain, then still requires the handle count to
be exactly zero. Raw bootstrap functions are removed before application code.

### 3.15 SQLite — host module, **capability-bearing** *(already built)*

Author-required, 2026-09-07. The predecessor's `@exact/sqlite` is not the
Ibex2 implementation. Ibex2 defines executor-independent typed contracts in
`stdlib::sqlite`; the separately linked `ibex2-sqlite` provider supplies native
SQLite. `Host::with_sqlite_provider` and `Hermes::set_sqlite_provider` install
it explicitly. No provider means a clear refusal, and no database opens during
binding installation. Ibex2's production library carries no SQLite dependency.

`Bindings.sqlite.open(path)` admits `sqlite.open` against a database path,
including `app:/data/name.db`. The host owns and keeps the database's parent
ancestry stable while connections are open. App paths refuse symlinks and
check the configured directory identity before opening; native paths check
spelling and realization. This is an in-process capability boundary, not a
sandbox against concurrent changes by another host process. SQLite owns its
native journals, locking, and crash recovery.

Rust databases expose `prepare`, `execute`, `query`, `transaction`, and `close`;
prepared statements expose `execute`, `query`, and `close`. JS receives a
frozen `sqlite` module parameter (after `__ibex2_meta` in the wrapper), never a
global. Its same methods return promises and serialize operations per database.
Transactions take a batch of `{sql, params}` commands and execute under one
immediate transaction; any failure rolls the batch back. Arbitrary async
transaction callbacks and manual transaction-control SQL are excluded.

SQL is exactly one statement per command. Values are bound, never interpolated:
null, signed 64-bit integers, finite reals, text including NUL, and byte blobs.
JS integers return as `BigInt`; unsafe integer-number inputs are rejected.
Queries return `{columns, rows}`, preserving duplicate column names, with a
16 MiB / 100,000-row ceiling. Queries are read-only; row-producing mutations
are rejected. Batch size is at most 10,000 commands. Schema and row writes use
`execute`; the result contains `changes` and `lastInsertRowid`. Prepared plans
are cached by the provider. Closing a database invalidates its statements.

The native authorizer denies attachment, detachment, extension loading, unsafe
PRAGMAs, and SQL paths that could widen the admitted file access (including
`VACUUM INTO`). Temporary SQL files are disabled, defensive mode is enabled,
and schemas are untrusted. Database result records cross as typed primitives
and private handles, never JSON. Native owners release collected JS handles;
pending operations retain their owners through settlement. Runtime destruction
closes outstanding databases off the engine thread.

Evidence: the provider's real-database tests and Ibex2's Rust and hardened
Hermes storage integration tests cover persistence, bound values, rollback,
connection/statement lifetime, module grants, and refused SQL filesystem access.

## 4. Capability summary

| API | capability | granularity |
|---|---|---|
| `fetch` | `net.fetch` | per-origin |
| `WebSocket` | `net.websocket` | per-origin |
| `fs` | `fs.read` / `fs.write` | per path prefix |
| `localStorage` | `storage.local` | per-application |
| `process.env` | `env.read` | per-variable |
| SQLite | `sqlite.open` | per database path |
| everything else in §3 | none | — |

Six capabilities, and the three that carry the supply-chain story are
`net.*`, `fs.*`, and `env.read` — network egress, filesystem reach, and
secrets. `crypto.subtle` and `Buffer` are deliberately ungated: they compute,
they do not reach. Compare the current design, whose registry is 4.16MB and
whose remaining admission work LLP 0039 records as roughly 16,628 unresolved
rows. The reduction is not a simplification of policy; it is what happens when
the enforcement point stops being every bare global reference.

## 5. Standing v1 exclusions

No general-purpose streams (`ReadableStream`, `WritableStream`,
`TransformStream`), workers, `SharedArrayBuffer`, or `Atomics`.
The author-required response reader in §3.5 removes whole-body-only fetch;
request streaming and stream transforms remain deferred. Buffered helpers
continue to collect with the caller's ceiling.
